# Parent Guardian Portal - Implementation Guide

## Overview
The Parent Guardian Portal is a read-only interface that allows parents, guardians, and other authorized users to monitor their linked student's academic progress, attendance, and upcoming assessments without accessing sensitive administrative functions.

## Architecture & Security

### Role-Based Access Control (RBAC)
- **GUARDIAN Role**: New user role added to the User model
- **Frontend Routes**: Protected by layout-level authentication that redirects unauthorized users to `/guardian/login`
- **API Endpoints**: Protected by `withAuth` middleware that validates user role

### Row-Level Security (RLS)
Every API endpoint implements strict row-level security to prevent guardians from accessing data they're not authorized to see:

1. **GuardianStudent Junction Table**: Links guardians to students with a unique constraint `(guardianId, studentId)`
2. **Verification Status**: Relationships can be marked as verified/unverified
3. **Data Filtering**: All API responses filter data based on the authenticated user's guardian relationships

### Threat Prevention
- ✅ Guardians cannot access other families' data by manipulating URL parameters
- ✅ All student IDs in API calls are verified against the guardian's linked students
- ✅ Sensitive data (ID numbers, administrative information) is excluded from responses
- ✅ API endpoints enforce 403 Forbidden response for unauthorized access attempts
- ✅ Audit logging captures all access attempts (via existing AuditLog system)

## Database Schema

### User Model Extension
```prisma
model User {
  // ... existing fields ...
  role String @default("FACILITATOR") // Now supports: FACILITATOR | ADMIN | GUARDIAN
  guardianStudents GuardianStudent[] @relation("GuardianUser")
  @@index([role])
}
```

### GuardianStudent Junction Table
```prisma
model GuardianStudent {
  id                String   @id @default(uuid())
  guardianId        String
  studentId         String
  relationshipType  String   @default("PARENT") // PARENT | GUARDIAN | OTHER
  verificationCode  String?  // Code used for initial linking (implementation detail)
  verifiedAt        DateTime?
  isVerified        Boolean  @default(false)
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt
  
  guardian          User     @relation("GuardianUser", fields: [guardianId], references: [id], onDelete: Cascade)
  student           Student  @relation(fields: [studentId], references: [id], onDelete: Cascade)

  @@unique([guardianId, studentId])
  @@index([guardianId])
  @@index([studentId])
  @@index([isVerified])
  @@index([createdAt])
}
```

### Student Model Extension
```prisma
model Student {
  // ... existing fields ...
  guardians GuardianStudent[] @relation
}
```

## API Endpoints

### Guardian Authentication
**POST `/api/auth/login`** (existing endpoint)
- Used by guardians to log in
- Role must be "GUARDIAN" after successful authentication
- Redirects to `/guardian/dashboard` on frontend

### Student Management
**GET `/api/guardian/students`**
- Returns all students linked to authenticated guardian
- Only verified relationships are included
- Response includes restricted fields:
  - Student name
  - Current module with number and name
  - Progress percentage
  - Credits earned
  - Status
  - Attendance rate for current month
  - Upcoming assessment dates (up to 5)
  - Recent grades (up to 5, with scores and dates)
- No sensitive data like ID numbers or other students' info

**GET `/api/guardian/students/[studentId]`**
- Returns detailed read-only information for a specific student
- Row-level security check: Verifies guardian has access to this student
- Returns:
  - Student overview (name, status, enrollment date, progress, credits)
  - Progress timeline (module-by-module breakdown with dates and status)
  - Attendance calendar (current month with daily records)
  - Assessment history (upcoming and completed assessments with scores/feedback)
  - Unit standard progress (completion status for each unit)
- Returns 403 Forbidden if guardian doesn't have access

### Student Linking
**POST `/api/guardian/link-student`**
- Allows guardians to link a student using verification code
- Request body:
  ```json
  {
    "studentId": "student-uuid",
    "verificationCode": "ABCD1234",
    "relationshipType": "PARENT" // Optional: PARENT | GUARDIAN | OTHER
  }
  ```
- Verification code generated by facilitators/admins
- Creates GuardianStudent relationship with isVerified = true
- Returns 400 if student already linked
- Returns 404 if student not found

### Admin Endpoints

**POST `/api/admin/generate-guardian-code`**
- Generates verification code for guardian to link student
- Only accessible by FACILITATOR and ADMIN roles
- Facilitators can only generate codes for their own students
- Request body:
  ```json
  {
    "studentId": "student-uuid"
  }
  ```
- Response includes:
  - 8-character alphanumeric code
  - Student name
  - Expiration time (24 hours)
  - Instructions for guardian
- Rate limited to prevent abuse

**GET `/api/admin/guardian-links`**
- Lists all guardian-student relationships
- Admin-only endpoint
- Supports filtering:
  - `?studentId=id` - Filter by student
  - `?guardianId=id` - Filter by guardian
  - `?verified=true|false` - Filter by verification status

**DELETE `/api/admin/guardian-links/[id]`**
- Revokes guardian access to a student
- Admin-only endpoint
- Use with caution - immediately revokes all access

## Frontend Routes

### Protected Routes (Require GUARDIAN Role)
- `/guardian/dashboard` - Main dashboard showing linked students
- `/guardian/students/[studentId]` - Student detail view
- `/guardian/settings` - Guardian settings page

### Public Routes
- `/guardian/login` - Guardian login page (redirects to dashboard if already logged in)

### Route Protection Mechanism
```typescript
// src/app/guardian/layout.tsx
export default function GuardianLayout({ children }: { children: React.ReactNode }) {
  const { user, isLoading } = useAuth();
  const router = useRouter();

  useEffect(() => {
    if (!isLoading && (!user || user.role !== 'GUARDIAN')) {
      router.push('/guardian/login');
    }
  }, [user, isLoading, router]);

  // Layout that protects all child routes
}
```

## Frontend Components

### GuardianDashboard (`/guardian/dashboard`)
- Shows grid of linked students with summary cards
- Each card displays:
  - Student name and status
  - Current module
  - Progress bar
  - Attendance rate (color-coded)
  - Credits earned
  - Recent grades (up to 3)
  - Upcoming assessments count
- "Link Student" button opens modal
- Clicking a student card navigates to detail view

### LinkStudentModal
- Modal component for linking new student
- Form fields:
  - Student ID (text input)
  - Verification Code (text input)
  - Relationship Type (select dropdown: Parent/Guardian/Other)
- Validation and error handling
- Success message on completion

### StudentDetail (`/guardian/students/[studentId]`)
- Tabbed interface with three sections:
  1. **Overview Tab**
     - Summary cards (progress, credits, attendance rate, enrollment date)
     - Progress timeline (module-by-module breakdown)
     - Status badges with color coding
   
  2. **Attendance Tab**
     - Month and attendance statistics (total days, present, absent)
     - Daily records with status (Present/Absent)
     - Scrollable list of records
   
  3. **Assessments Tab**
     - Upcoming assessments (with due dates and unit standard info)
     - Completed assessments (with scores, feedback, dates)
     - Separated views for better clarity

## Verification Code System

### Current Implementation
- 8-character alphanumeric codes generated by POST `/api/admin/generate-guardian-code`
- Codes are shown to facilitators who share with guardians
- Verification happens on `/api/guardian/link-student` endpoint

### Recommended Enhancement
For production, consider implementing:
1. **VerificationCode Model** in Prisma:
   ```prisma
   model VerificationCode {
     id        String   @id @default(uuid())
     code      String   @unique
     studentId String
     createdBy String   // Facilitator/Admin who generated
     expiresAt DateTime // 24 hours from generation
     usedAt    DateTime? // When/if used
     usedBy    String?   // Guardian who used it
     
     student   Student  @relation(fields: [studentId], references: [id])
     creator   User     @relation(fields: [createdBy], references: [id])
   }
   ```

2. **Code Validation Logic**:
   - Check code exists
   - Verify not expired
   - Verify not already used
   - Verify studentId matches linked student

3. **Code Expiration Enforcement**:
   - Cleanup job to remove expired codes
   - Real-time expiration check on usage

## Security Best Practices Implemented

✅ **Authentication & Authorization**
- JWT-based authentication (existing implementation)
- Role-based access control for endpoints
- Layout-level route protection on frontend

✅ **Data Access Control**
- Row-level security on all guardian endpoints
- Verification of guardian-student relationship before data return
- No data exposure through URL parameter manipulation

✅ **Data Minimization**
- Only relevant fields returned to guardians
- No sensitive administrative data exposed
- No cross-family data exposure

✅ **API Security**
- Rate limiting on all endpoints
- Input validation with Zod schemas
- Error responses don't leak sensitive information
- HTTP security headers applied

✅ **Audit & Logging**
- All access attempts logged via AuditLog
- Guardian role can be tracked
- Data access patterns can be audited

## Usage Workflow

### For Facilitators: Generating Link Code
1. Access admin endpoint: `POST /api/admin/generate-guardian-code`
2. Provide studentId
3. Receive 8-character code
4. Share code with guardian via email/messaging

### For Guardians: Linking a Student
1. Visit `/guardian/login` and sign in
2. Click "Link Student" button on dashboard
3. Enter student ID (provided by facilitator)
4. Enter verification code (provided by facilitator)
5. Select relationship type (Parent/Guardian/Other)
6. Click "Link Student" button
7. Access student's data on dashboard

### For Guardians: Monitoring Student
1. View student summary on dashboard
2. Click student card to view full details
3. Check overview tab for progress timeline
4. Check attendance tab for monthly attendance
5. Check assessments tab for grades and upcoming tests

## Troubleshooting

### Guardian Can't Login
- Check that user role is set to "GUARDIAN" in database
- Verify password is correct
- Check browser console for error messages
- Verify JWT token generation works

### Guardian Sees "No Students Linked"
- Confirm GuardianStudent record exists with isVerified=true
- Check student hasn't been deleted
- Verify API is returning student list correctly
- Check network requests in browser

### Row-Level Security Errors (403 Forbidden)
- Verify GuardianStudent relationship exists
- Check isVerified flag is set to true
- Confirm correct studentId in request
- Review audit logs for access attempts

### Verification Code Issues
- Verify code format matches (alphanumeric, 8 characters)
- Check code hasn't expired (24-hour window in current implementation)
- Verify studentId in link request matches code generation
- Check for case sensitivity in code validation
